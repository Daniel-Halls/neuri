### Nipype Core Pipeline Engine Constructs

Nipype’s workflow execution framework is managed by the pipeline engine (`nipype.pipeline.engine`), which organizes data processing into Directed Acyclic Graphs (DAGs) [1-3].

#### 1. `Workflow` (`nipype.pipeline.engine.Workflow`)
* **What it does**: Represents an entire pipeline or sub-pipeline graph connecting processing nodes together [1-3].
* **Arguments / Parameters**:
  * `name` (*string*): Unique identifier for the workflow instance [1, 2, 4].
  * `base_dir` (*path string*): Root working directory where node execution folders and intermediate cached outputs are stored [2, 4, 5].
  * `config` (*dict*): Configuration options (e.g., setting crashdump directories or enabling execution logging) [6, 7].
* **Key Methods**:
  * `.connect([(node1, 'output_field', node2, 'input_field')])`: Defines directed data edges between nodes [1, 4].
  * `.run(plugin=None, plugin_args=None)`: Executes the workflow graph locally or using parallel execution plugins (e.g., `MultiProc`, `SGE`, `PBS`) [8-11].
  * `.write_graph()`: Generates graphical representations (DOT/PNG) of the workflow topology [8, 9, 12].
* **Use Case**: Encapsulating complete multi-stage pipelines such as fMRI first-level preprocessing, surface-based analysis, or DTI reconstruction [2, 4, 13].

#### 2. `Node` (`nipype.pipeline.engine.Node`)
* **What it does**: Wraps an individual Nipype Interface (such as an FSL or SPM command) to handle execution sandboxing, input checking, output tracking, and hash-based caching [14-16].
* **Arguments / Parameters**:
  * `interface` (*Interface instance*): The underlying command interface class [14, 15].
  * `name` (*string*): Unique name for the node within the parent workflow [14, 15].
  * `iterables` (*tuple*): Specifies parameters to sweep over (e.g., subject IDs or smoothing kernel widths), triggering parallel pipeline branches [14, 17, 18].
* **Use Case**: Executing single processing steps like skull-stripping or motion correction within a pipeline [14, 15, 19].

#### 3. `MapNode` (`nipype.pipeline.engine.MapNode`)
* **What it does**: Extends `Node` to iterate an interface over a list of inputs (e.g., multiple functional runs or contrast files) independently and in parallel [20-23].
* **Arguments / Parameters**:
  * `interface`, `name`: Standard node specifications [20-22].
  * `iterfield` (*list of strings*): Names of input fields that contain lists of items to be mapped over [20-23].
* **Use Case**: Applying single-file operations (such as converting image formats, fitting GLMs across runs, or smoothing) to every item in a list [22-25].

#### 4. `JoinNode` (`nipype.pipeline.engine.JoinNode`)
* **What it does**: Collects and recombines distributed outputs generated by upstream parameterized branches (e.g., from `iterables` or `MapNode` operations) back into a single unified list or stream.
* **Arguments / Parameters**:
  * `interface`, `name`: Standard node specifications.
  * `joinsource` (*string*): Name of the upstream node whose parallel branches are being merged.
  * `joinfield` (*list of strings*): Input fields designated to aggregate the incoming branch data.
* **Use Case**: Aggregating single-subject analysis results across a cohort into a list for second-level group statistics.

### Data I/O & Utility Interfaces

Nipype provides specialized interfaces in `nipype.interfaces.io` and `nipype.interfaces.utility` to manage file finding, data routing, and result storage [26-28].

#### 1. `DataGrabber` (`nipype.interfaces.io.DataGrabber`)
* **What it does**: Fetches files from disk using flexible template strings and `glob` patterns [14, 15, 29].
* **Parameters**:
  * `base_directory` (*path*): Root folder where datasets reside [15, 30].
  * `template` (*string*): String template pattern for file matching (e.g., `'%s/%s.nii'`) [15, 31].
  * `template_args` (*dict*): Specifies parameters to plug into the template string [15, 31].
  * `infields` / `outfields` (*lists*): Dynamically created input and output port names [14, 29, 31].
* **Use Case**: Dynamically querying and ingesting subject structural and functional files into a pipeline [14, 15].

#### 2. `DataSink` (`nipype.interfaces.io.DataSink`)
* **What it does**: Copies and organizes selected output files from workflow scratch folders into an organized output directory structure [32-34].
* **Parameters**:
  * `base_directory` (*path*): Target destination directory [30, 33, 35].
  * `container` (*string*): Top-level subject/session folder name inside the base directory [30, 35].
  * `substitutions` / `regexp_substitutions` (*list of tuples*): String/regex replacement patterns used to clean up output file/folder names [30, 36-38].
* **Use Case**: Storing published images, contrast maps, and QA reports in clean directory structures [33-35].

#### 3. `SelectFiles` (`nipype.interfaces.io.SelectFiles`)
* **What it does**: Ingests files using standard Python format string syntax (e.g. `{subject_id}/func/{run}.nii.gz`), offering a simpler syntax than `DataGrabber` [39, 40].
* **Parameters**:
  * `templates` (*dict*): Key-value dictionary mapping output keys to Python formatting strings [40].
  * `base_directory` (*path*): Base path for path resolution [40].
* **Use Case**: Standardized data ingestion using explicit string formatting rules.

#### 4. `BIDSDataGrabber` (`nipype.interfaces.io.BIDSDataGrabber`)
* **What it does**: Wraps PyBIDS to query BIDS datasets based on standard BIDS entities (subject, session, run, task) [41].
* **Parameters**:
  * `base_dir` (*path*): Path to the BIDS dataset root [41, 42].
  * `subject` (*string/list*): Target subject identifier(s) [41, 42].
  * `output_query` (*dict*): Custom queries defining specific output file types [42].
* **Use Case**: Directly ingesting files from BIDS-compliant raw or derivative datasets [41, 42].

#### 5. `FreeSurferSource` (`nipype.interfaces.io.FreeSurferSource`)
* **What it does**: Automatically locates and parses output files from a FreeSurfer subject folder (`recon-all` outputs) [19, 43, 44].
* **Parameters**:
  * `subjects_dir` (*path*): Path to FreeSurfer subjects directory [44].
  * `subject_id` (*string*): Subject directory name [44].
  * `hemi` (*'lh'*, *'rh'*, or *'both'*): Hemisphere selection [44].
* **Outputs**: Provides attributes for key volumes and surfaces (`orig`, `brainmask`, `aseg`, `wm`, `pial`, `white`, `inflated`, `sphere`) [19, 45, 46].
* **Use Case**: Exposing FreeSurfer structural surfaces and anatomical segmentations to downstream workflows [19, 45].

#### 6. `IdentityInterface` (`nipype.interfaces.utility.IdentityInterface`)
* **What it does**: A pass-through utility interface that exposes specified fields without modification [17, 47-49].
* **Parameters**:
  * `fields` (*list of strings*): Names of input/output ports to create [47-49].
* **Use Case**: Acting as workflow input/output specification containers (`inputnode`/`outputnode`) or driving subject loops in combination with `iterables` [17, 21, 47, 49].

### Package Interfaces

Nipype provides standardized Python wrappers across third-party neuroimaging suites [50, 51].

```
                          ┌───────────────────────────┐
                          │   Nipype Workflow Engine   │
                          └─────────────┬─────────────┘
                                        │
           ┌────────────────────┬───────┴────────────┬───────────────────┐
           ▼                    ▼                    ▼                   ▼
    ┌─────────────┐      ┌─────────────┐      ┌─────────────┐     ┌─────────────┐
    │     FSL     │      │     SPM     │      │    AFNI     │     │ FreeSurfer  │
    └──────┬──────┘      └──────┬──────┘      └──────┬──────┘     └──────┬──────┘
           │                    │                    │                   │
  • BET                • Realign            • Despike           • ReconAll
  • FLIRT / FNIRT      • Coregister         • Volreg            • BBRegister
  • ApplyWarp/ApplyXFM • Segment            • AlignEpiAnatPy    • ApplyVolTransform
  • MCFLIRT / FAST     • Normalize          • Allineate         • MRIConvert
  • FEAT / FILMGLS     • Smooth             • Deconvolve        • Binarize
  • FLAMEO             • SliceTiming        • TProject          • SegStats
```

#### A. FSL Interfaces (`nipype.interfaces.fsl`)

* **`BET`**: Wraps FSL Brain Extraction Tool for skull-stripping [52, 53].
  * *Parameters*: `in_file` [52, 53], `out_file` [52], `mask` (creates binary mask) [52], `frac` (intensity threshold) [52], `robust` [52].
  * *Use Case*: Extracting brain tissue from structural T1w or functional volumes [52, 54].
* **`FLIRT`**: Wraps FMRIB's Linear Image Registration Tool for affine registration [55, 56].
  * *Parameters*: `in_file` [55], `reference` [55], `out_matrix_file` (`-omat`) [57, 58], `cost` (`mutualinfo`, `bbr`, `corratio`) [55], `dof` (degrees of freedom: 6, 7, 9, 12) [59].
  * *Use Case*: Linear inter-modal coregistration and affine standard space alignment [59, 60].
* **`ApplyXFM`**: Light wrapper around `FLIRT` specifically for applying saved transformation matrices [60].
  * *Parameters*: `in_file`, `in_matrix_file`, `reference`, `apply_xfm=True`, `interp` (`trilinear`, `nearestneighbour`, `sinc`) [60, 61].
  * *Use Case*: Applying rigid/affine transforms to functional volumes or ROI masks [60, 61].
* **`FNIRT`**: Wraps FMRIB's Nonlinear Image Registration Tool for non-linear registration [62, 63].
  * *Parameters*: `in_file` [62], `ref_file` [62], `affine_file` (`--aff`) [63], `config` (e.g. `T1_2_MNI152_2mm`) [62, 64], `fieldcoeff_file` (`--cout`) [62].
  * *Use Case*: High-accuracy non-linear warping of structural images to MNI space [62, 64].
* **`ApplyWarp`**: Applies `FNIRT` non-linear warp fields to target datasets [65, 66].
  * *Parameters*: `in_file` [65], `ref_file` [65], `field_file` (`--warp`) [65], `premat` (affine matrix) [67].
  * *Use Case*: Resampling functional or structural data into standard space via non-linear warps [65, 68].
* **`MCFLIRT`**: Performs rigid-body motion correction on 4D functional series [69-71].
  * *Parameters*: `in_file` [69, 71], `cost` [71], `save_plots` (saves 1D motion parameters).
  * *Use Case*: Intra-run volume realignment for fMRI time series [69, 71].
* **`FAST`**: Performs tissue-type segmentation (CSF, GM, WM) and spatial intensity bias correction [72, 73].
  * *Parameters*: `in_files` [72, 74], `number_classes` (default 3) [72]. Outputs `partial_volume_files` [74].
  * *Use Case*: Generating tissue probability maps for nuisance regression (e.g., CompCor) [74].
* **`FIRST`**: Performs model-based subcortical brain structure segmentation [72, 75].
  * *Parameters*: `in_file` [72], `list_of_specific_structures` (e.g. caudate, hippocampus) [75].
  * *Use Case*: Automated subcortical ROI segmentation [75, 76].
* **fMRI Modeling (`Level1Design`, `FEATModel`, `FILMGLS`, `ContrastMgr`, `FLAMEO`)**:
  * *Parameters*: `Level1Design` creates FEAT `.fsf` scripts [22, 77]; `FEATModel` generates `.mat` design matrices [22, 25]; `FILMGLS` fits voxelwise GLMs with prewhitening [25]; `ContrastMgr` computes contrast statistics [25]; `FLAMEO` estimates group-level models [78, 79].
  * *Use Case*: End-to-end first-level and higher-level fMRI GLM analysis [22, 25, 78].
* **`ImageMaths`**: Wraps `fslmaths` for voxelwise arithmetic operations and thresholding [21, 80, 81].
  * *Parameters*: `in_file` [80], `op_string` (e.g., `-thr 0.9 -ero -bin`) [21, 80].

#### B. SPM Interfaces (`nipype.interfaces.spm`)

* **`Realign`**: Performs rigid-body 3D volume realignment across fMRI series [82, 83].
  * *Parameters*: `in_files` [83], `register_to_mean=True` [82, 83]. Outputs `realigned_files`, `mean_image`, `realignment_parameters` [4, 82, 83].
  * *Use Case*: Motion correction in SPM-based fMRI pipelines [82, 83].
* **`Coregister`**: Performs rigid-body multi-modal coregistration using mutual information [84, 85].
  * *Parameters*: `target` (reference T1w) [84, 85], `source` (mean EPI) [84, 85], `apply_to_files` (functional series) [4, 85], `jobtype` (`'estimate'`, `'write'`, `'estwrite'`) [84, 85].
  * *Use Case*: Registering functional EPIs to structural anatomical images [84, 85].
* **`Segment`**: Unified segmentation algorithm performing tissue classification, bias field estimation, and spatial normalization parameter calculation [24, 86, 87].
  * *Parameters*: `data` [88], `save_bias_corrected` [89]. Outputs `transformation_mat` [88].
  * *Use Case*: Tissue segmentation and generating normalization parameters [24, 88].
* **`Normalize`**: Normalizes images to standard template space using unified segmentation transformation matrices [85, 86].
  * *Parameters*: `parameter_file` (`transformation_mat`), `apply_to_files`, `template`, `write_voxel_sizes` [85, 86, 88].
  * *Use Case*: Spatial normalization of functional or structural images to MNI space [85, 86].
* **`Smooth`**: Applies 3D Gaussian spatial smoothing [83-85, 90].
  * *Parameters*: `in_files` [83-85], `fwhm` (kernel FWHM in mm) [83-85].
  * *Use Case*: Spatial smoothing of functional data prior to statistical modeling [85, 90].
* **`SliceTiming`**: Corrects slice acquisition time differences across 3D slices within a volume [91].
  * *Parameters*: `in_files`, `num_slices`, `TR`, `slice_order`, `ref_slice` [91].
* **`SpecifyModel` (`nipype.algorithms.modelgen.SpecifyModel`)**: Abstract model specification interface converting event files and motion parameters into GLM design structures [22, 92, 93].
  * *Parameters*: `subject_info` (`Bunch` objects with onsets/durations) [22, 92], `time_repetition` (TR) [92], `functional_runs` [92, 94], `realignment_parameters` [94, 95].

#### C. AFNI Interfaces (`nipype.interfaces.afni`)

* **`Despike`**: Wraps `3dDespike` to eliminate transient intensity spikes in fMRI time series [96-98].
  * *Parameters*: `in_file` [96], `out_file` (`-prefix`) [98].
  * *Use Case*: Pre-preprocessing cleanup of EPI data [96].
* **`Volreg`**: Wraps `3dvolreg` for 3D rigid-body motion correction [99, 100].
  * *Parameters*: `in_file` [100], `basefile` (reference volume or `MIN_OUTLIER`) [101, 102], `oned_file` (`-1Dfile` for motion parameters) [100, 102], `zpad` [100, 102].
  * *Use Case*: EPI volume realignment [100, 101].
* **`AlignEpiAnatPy`**: Wraps `align_epi_anat.py` for EPI-to-structural alignment [103].
  * *Parameters*: `anat`, `epi`, `cost` (`lpc`, `lpc+ZZ`, `lpa`) [101, 103].
* **`Allineate`**: Wraps `3dAllineate` for general linear volume registration [104, 105].
  * *Parameters*: `in_file` (`-source`), `reference` (`-base`), `in_matrix` (`-1Dmatrix_apply`), `cost` (`lpc`, `lpa`, `nmi`) [104-106].
* **`AutoTLRC`**: Wraps `@auto_tlrc` to linearly transform anatomical volumes into Talairach/MNI space [107].
  * *Parameters*: `in_file`, `base` (template volume) [101, 108].
* **`Deconvolve`**: Wraps `3dDeconvolve` for multiple linear regression and deconvolution analysis [109, 110].
  * *Parameters*: `in_files` [110], `stim_times` [110], `stim_label` [110], `gltsym` [110], `x1D` (design matrix output) [110], `out_file` (`-bucket`) [110].
  * *Use Case*: Task fMRI first-level GLM estimation [109, 110].
* **`TProject`**: Wraps `3dTproject` to project out nuisance regressors (motion, WM/CSF signals, bandpass filters) via linear regression [111].
  * *Parameters*: `in_file`, `ort` (nuisance matrix), `bandpass`, `mask` [111].
* **`Calc`**: Wraps `3dcalc` for voxelwise mathematical calculations [112-114].
  * *Parameters*: `in_file_a` [114], `in_file_b` [114], `expr` (expression string) [112, 114], `out_file` [114].

#### D. FreeSurfer Interfaces (`nipype.interfaces.freesurfer`)

* **`ReconAll`**: Wraps FreeSurfer's `recon-all` pipeline for automated cortical reconstruction, subcortical segmentation, and surface generation [115-118].
  * *Parameters*: `subject_id` [118], `subjects_dir` [115, 118], `directive` (`'all'`, `'autorecon1'`, `'autorecon2'`, `'autorecon3'`) [116, 119, 120], `T1_files` [121].
  * *Use Case*: Surface reconstruction and anatomical parcellation from T1w images [116, 117].
* **`BBRegister`**: Boundary-based registration (`bbregister`) aligning functional or diffusion volumes to FreeSurfer anatomical surfaces [19, 122, 123].
  * *Parameters*: `subject_id` [19, 123], `source_file` (mean EPI) [123], `contrast_type` (`'t1'`, `'t2'`, or `'bold'`) [19, 123], `init` (`'fsl'`, `'coreg'`, `'header'`) [19, 123], `subjects_dir` [123].
  * *Use Case*: High-precision EPI-to-structural coregistration using tissue boundaries [19, 123].
* **`ApplyVolTransform`**: Applies FreeSurfer transform matrices (`.dat`, `.lta`, `.mat`) via `mri_vol2vol` [19, 124].
  * *Parameters*: `source_file` [124], `target_file` [125, 126], `reg_file` [125, 126], `inverse` [90], `interp` (`'trilinear'`, `'nearest'`, `'cubic'`) [24, 74].
  * *Use Case*: Resampling volumes between native EPI space and FreeSurfer anatomical space [19, 74].
* **`MRIConvert`**: Wraps `mri_convert` for format conversion, volume grid conforming, and resampling [24, 127].
  * *Parameters*: `in_file` [127], `out_file` [127], `out_type` (`'nii'`, `'mgz'`, `'nii.gz'`) [24, 127].
  * *Use Case*: Converting FreeSurfer `.mgz` files to NIfTI format [24, 127].
* **`Binarize`**: Wraps `mri_binarize` for volume thresholding and binary mask creation [90, 128].
  * *Parameters*: `in_file` [128], `min` [90], `match` (specific segmentation IDs) [54], `binary_file` [126, 129].
  * *Use Case*: Creating binary brain or tissue masks from segmentation volumes [54, 90].
* **`SegStats`**: Wraps `mri_segstats` to calculate volume and intensity summary statistics within segmented ROIs [20, 130-132].
  * *Parameters*: `segmentation_file` (`--seg`) [20, 131], `in_file` (`--in`) [20, 131], `avgwf_txt_file` (saves mean ROI time series to text) [20, 132], `summary_file` [20, 132].
  * *Use Case*: Extracting regional average time series or ROI volumes [20, 131].
* **`MRISPreproc`**: Wraps `mris_preproc` to resample surface data across subjects onto a common spherical template (e.g. `fsaverage`) [133-135].
  * *Parameters*: `target` (e.g. `'fsaverage'`) [135], `hemi` (`'lh'` or `'rh'`) [135], `out_file` [135], `vol_measure_file` [135].
  * *Use Case*: Group surface-based fMRI or structural morphometry analysis [135].
